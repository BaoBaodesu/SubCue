## 1. 目标、定位与边界

### 1.1 产品定位

在 SubCue 现有字幕/粗剪能力旁新增 **AI 配音（Voice Studio）Workspace**，用于：

- 为不同角色建立**可自定义名称**的声音档案，支持新增、重命名、复制预设、切换音色和版本回退；内部使用稳定 UUID，不能用可变名称作为主键。
- 从一段干净声音快速克隆；或导入多段中英日素材构建**高质量参考音色库**，不要求每个角色必须训练独立权重。
- 自动预处理、质量评估、音频切分、语言/转写与可选的**情绪初步标注**；不确定的标注需显式展示并允许修正。
- 通过文字生成中、英、日语音，允许单语、跨语言及混语片段；评估音色相似度、发音、口音和稳定性，不能保证完全无口音。
- 从外部 LLM 网页**粘贴自由文本或结构化配音方案**；可逐段编辑情绪、断句、语速、停顿、参考样本和朗读文本。
- 支持**仅重新生成被修改片段**，管理候选音频、生成历史、撤销/重做、时间轴更新与拼接；不重写未修改片段。
- 同一套声音档案对接本地推理、用户自训练并下载到本地的权重，以及需要云端 Voice ID 的托管 API。
- 保持 SubCue 的 C++20 + Qt 6 / QML / FFmpeg 技术栈、离线优先策略与可审计的数据存储。

### 1.2 明确不在本阶段实施

- 不训练任何模型，不下载权重，不下载额外 ASR/情绪识别模型；保留后续训练和推理接口。
- 不接入、试用、付费或验证任何真实云端 TTS/声音注册 API；不将占位符误标为已支持服务。
- 不在 SubCue 中开发内置“导演 AI”聊天/推理功能。
- 不实现完整 DAW、复杂实时变声、声纹身份验证体系、未经验证的逐字波形修补。
- 不承诺 V0 阶段达到商业级声音克隆质量；真实模型验收只能在后续下载/部署后进行。

### 1.3 三个概念务必分离

| 概念 | 本地持有资产 | 推理是否必须联网 | 后续处理 |
|---|---|---|---|
| **零样本声音档案** | 参考 WAV、转写、参考选择、可能的特征缓存 | 否（本地引擎已安装时） | 一次建档，反复复用 |
| **专属微调音色** | 原始素材、配置、可下载的微调权重/适配器（视训练实现而定） | 否（兼容本地引擎已安装时） | 需要记录基础模型与权重依赖 |
| **云端托管音色** | Voice ID、Provider 映射、必要元数据与本地授权素材 | 是 | Voice ID **不是**可下载的模型权重 |

> **硬约束**：将来如果要求“云端训练完下载权重到本地”，只能选择**确实支持导出权重的云 GPU 自训练流程**或明确支持导出的服务。不能把托管音色注册 API 返回的 Voice ID 当作本地模型文件。

### 3.1 进程与职责

- **UI/Main 进程**：界面、档案管理、脚本操作、任务状态、音频预览；**不得在 UI/实时音频回调线程中运行 GPU 推理、同步磁盘 IO 或网络调用**。
- **C++ 核心**：负责资产生命周期、FFmpeg 处理、持久化、统一任务模型、撤销与恢复、Provider 能力判断。
- **独立模型进程**：待部署时通过现有 Worker 或 `QProcess` + 本机 IPC（待审查决定）承载各 Python/PyTorch 引擎，隔离依赖和崩溃。
- **云端 Provider**：只作为可关闭的适配器；允许强制本地模式、联网前确认、权限/价格上限、错误码映射与取消。
- **Mock Provider**：开发和自动化测试的默认引擎，不依赖模型下载、GPU 或 Key，可输出测试音频及模拟延迟/错误。

### 3.2 需讨论的接口草案（非要求立即落地的代码）

| 契约 | 核心字段或方法 | 需要确认的问题 |
|---|---|---|
| `VoiceProfile` | `uuid`, `displayName`, `aliases`, `defaultPresetId`, `assets`, `providerBindings` | 多名称、音色变体、删除依赖 |
| `ReferenceAsset` | `id`, 原始路径/哈希, 语种, 对齐文字, 情绪标签, 质量状态, consent/usage | 原始/清洗版本关系与复用 |
| `VoicePreset` | 选中参考片段、目标引擎、默认情绪、采样/声音版本 | 复制预设与兼容性校验 |
| `TtsCapabilities` | 语种、克隆方式、参考文字要求、情绪文本/向量/音频、流式、语速、上下文 | 不支持时显式降级，禁止“静默忽略” |
| `TtsRequest` | `requestId`, `profileId`, `segmentId`, 文本/语言, 风格指令, 上下文, 指定 Provider, 输出规格 | 兼容不同引擎，保持可追溯 |
| `TtsResult` | 音频资产、原生采样率、耗时、模型/版本、诊断、请求哈希 | 失败/取消/部分成功语义 |
| `ITtsProvider` | `capabilities()`, `validate()`, `synthesize()`, `cancel()`；音色注册/权重导入为可选扩展 | 同步抽象或异步任务模式 |
| `VoiceJob` | queued/running/completed/failed/canceled, progress, attempts, error | 重试、去重、恢复、资源队列 |

**原则**：角色名称不是文件路径或数据库主键；音色身份信息与情绪参考必须分离；同一角色可关联多个 Provider 的不同资产。

## 4. 声音档案与样本处理

### 4.1 两条建档路径

**A. 快速克隆**：导入单段授权的干净人声 → 检查质量 → 记录语言/必要转写 → 选择参考音频 → 建立角色档案。无模型时可完成建档，待模型安装后生成。

**B. 高质量档案（不强制微调）**：导入样本群 → 语音分段/音质检查 → ASR/语言与可选情绪标签 → 人工审核可疑样本 → 去重及说话人一致性检查 → 建立多样本参考池、默认参考与情绪预设 → 用标准测试语句对比（待引擎可用时）。

高质量档案的“高质量”应来自**样本选择和过程质量**，不是单纯累积时长或强制训练。

### 4.2 音频完整性与预处理

1. **原始素材永不覆盖**：保存原文件及 SHA-256、采样率、声道、时长、编码格式、来源与使用授权；所有处理写成可重现派生资产。
2. **内部处理格式建议**：Float32 PCM + 48kHz 作为 SubCue 时间轴/混音工作格式候选；模型专用参考缓存按其明确要求独立重采样，**不把所有模型输入硬编码成 48kHz**。
3. 通过 FFmpeg/libswresample 做真正重采样，保留时基/时长；严禁只改采样率标记。解码和重采样需验证声道布局、整数/浮点缓冲、端序。
4. 检测 DC Offset、Peak、True Peak、明显连续满幅削波、瞬态 Click/Pop、静音、噪声与混入背景声。检测值存证；阈值作为可调工程策略，不能等价于“超阈值必然不可用”。
5. **噪声处理默认保守**：对 50/60Hz 嗡声及其谐波做诊断，必要时可选陷波；一般底噪轻度降噪。避免把气声、齿音、角色音色特征全部滤掉。
6. 原始严重削波不能靠降音量恢复；先标记和剔除，De-clip 仅为可选修复并需人工确认。
7. 播放/拼接处的 Click/Pop 要单独定位：在段边界检查样本不连续、缓冲/设备采样率、过零点与短淡化，不误诊为录音底噪。
8. TTS 输出需经过独立质检：格式校验、溢出/削波/NaN、True Peak、峰值、静音、时长、声道一致性；输出响度策略与训练参考清洗策略不可混为一谈。
9. 标记音频修复前后 A/B 试听与审阅历史；支持仅保留清洗缓存或重新生成派生资产。

**建议但非硬门槛**：对需要明显余量的参考样本使用约 -3 dBFS 峰值目标；最终导出采用单独的 True Peak 和响度预设。所有数值在真实素材对照测试后定稿。

### 4.3 转写、情绪及角色一致性

- 优先复用已有 ASR/VAD 能力；未安装识别模型时，可手动输入转写与标签，不能阻止建档。
- 情绪识别器仅列候选（SenseVoice-Small、emotion2vec+），待后续单独部署；`predictedEmotion`、置信度、版本和 `manualEmotionOverride` 分开存储。
- 保留“未分类/不确定”，特别是害羞、傲娇、故作生气等复合表演，不能被硬映射为模型已经准确理解的情绪。
- 说话人一致性检查优先于情绪分类：混入旁白、旁人、BGM、对话重叠的样本应提示剔除或人工审核。
- 将样本用于零样本参考、情绪参考或微调语料的资格分开标记；**不要求微调数据必须具有情绪标签**。
- 不混入其他中文配音者的样本来“修正”原角色中文口音；目标语言发音用文本规范化、发音词典、换参考/引擎和效果测试处理。

### 4.4 跨语言质量

- 明确支持**源参考语种**与**合成目标语种**分别保存（ZH/EN/JA）；按片段确定目标语种，混语先支持显式分段。
- 参考语音仅为日文或英文时，中文结果可能保留口音或声调异常；**不可宣传完全消除口音**。
- 建立标准样本集：中文声调、多音字、数字、专有名词、英语连读、日语假名/汉字读音、三语切换。
- 质量分为：文字准确率（ASR 回读）、说话人相似度、口音/自然度、情绪贴合、爆音/失真；避免单一指标替代主观试听。

## 5. 脚本与局部重生成

### 5.1 外部 LLM 指令导入（不内置导演 AI）

- **普通粘贴**：接受自由表演指令，保留原文，提醒当前 TTS Provider 是否支持直接自然语言控制。
- **结构化粘贴**：接受经版本化 Schema 校验的 JSON；先预览影响，不自动覆盖现有台词；显示缺失字段、未知情绪、语言不符或会修改原文的位置。
- 支持手动编辑原始文本、朗读文本、目标语言、预设情绪、自由指令、停顿、断句、强调及参考样本。
- 输入始终视为**不可信内容**：禁止代码执行、任意文件 URL 自动读取、任意磁盘路径写入与外部指令覆盖应用安全规则。
- 对不支持的参数进行显式警告/降级提示，不得 UI 显示“已生效”但 Provider 实际忽略。

```json
      "spoken_text": "你终于回来了……",
      "language": "zh",
      "emotion": "relieved",

    }
  ]
}
```

### 5.2 片段数据和版本管理

- 数据层建议使用 **Scene → Paragraph → Segment → AudioTake**；文本、生成请求与成品音频一对多。
- 每个片段使用稳定 ID；修改断句时保留原始片段的溯源关系，避免原有时间轴引用指向错误。
- 仅标记**受影响的片段**为 stale；已生成音频不覆盖，另建 Take。修改角色默认参考会影响哪些片段必须明确列出。
- 导出音频从最终选择的 Take 拼接；支持撤销、重新选择旧版本、局部替换、缓存失效与重跑。
- 片段前后文（`previousText` / `nextText`）作为统一内部信息；Provider 不支持时不得假装已使用上下文。
- 不承诺精确“修改一个字但保持其他波形完全相同”；优先以短语/语句为重新生成单位。
- 完整生成记录包含 Provider、模型版本、角色预设版本、参考哈希、文本、可控参数、随机种子（若支持）与调用时间。

## 6. 模型、训练及云端 API：**只做清单和接口预留**

> 本章节不得触发模型下载、依赖安装、训练、云端账号授权、价格结算或 API 实际请求。官方功能可能随版本变更；实施前逐项复核许可证、参数、硬件条件、付费与隐私政策。

### 6.1 候选模型及未来接入优先级

| 类别 | 候选 | 待适配的核心能力 | 当前计划动作 |
|---|---|---|---|
| 本地零样本 TTS | [IndexTTS-2.5](https://github.com/index-tts/index-tts) | 音色参考、独立情绪参考/向量/文本、多语言 | **接口占位**；不下载 |
| 本地零样本 TTS | [Qwen3-TTS Base](https://github.com/QwenLM/Qwen3-TTS) | 参考音频+可选参考文字、可复用 Voice Clone Prompt、ZH/EN/JA | **接口占位**；不下载 |
| 本地微调 / TTS | [GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS) | 训练权重、默认参考音频及其对应文字、语言控制 | **接口占位**；不训练 |
| 可选识别 | [SenseVoice](https://github.com/FunAudioLLM/SenseVoice) | ASR、语言/情绪候选 | **清单**；不下载 |
| 可选情绪识别 | [emotion2vec](https://github.com/ddlBoJack/emotion2vec) | 情绪分类与人工覆盖 | **清单**；不下载 |
| 云端 TTS/音色注册 | 阿里云百炼 Qwen / CosyVoice | 注册音色、合成、风格指令、返回 Voice ID | **Provider 占位**；不连接 |
| 云端 TTS/音色注册 | ElevenLabs、MiniMax | 声音注册、合成、语音情绪、额度/权限 | **Provider 占位**；不连接 |
| 自主可下载微调 | 未来云 GPU 训练任务 | 提交训练数据、下载权重、导入本地 | **训练资产接口占位**；不执行 |

**注意**：Qwen3-TTS Base 的克隆接口和 CustomVoice/VoiceDesign 的指令接口不可混为同一能力；IndexTTS 情绪文本/向量与音频参考之间可能存在互斥关系；GPT-SoVITS 某些推理路径仍要求参考音频、参考文字。必须在 Provider 适配层体现这些差异，并把重复提供参考材料的流程隐藏在角色档案管理中。

### 6.2 待设计的 Provider 功能分组

- `LocalModelRegistry`：后续用户手动提供模型目录 → 版本/配置/校验和检查 → 能力发现 → 状态检测；**不得自动联网下载**。
- `ReferencePromptCache`：在运行时复用音色条件。是否能持久化到磁盘由具体模型/版本适配器决定，不能把内存对象一律序列化成通用文件。
- `LocalTtsProvider`：独立推理进程、按需加载、GPU 串行队列、显存不足错误处理、取消与重试。
- `FineTuneAssetRegistry`：识别权重格式、基础模型依赖、来源与许可证、导入和卸载；自训练尚不在实施范围。
- `CloudVoiceRegistry`：用户同意后注册 Voice ID、绑定 `provider/model/region/voiceId`、过期/不可用状态；不得将 Voice ID 当成离线模型。
- `CloudTtsProvider`：配置占位、功能查询、鉴权密钥引用、服务商返回的实际字符/Token 用量及金额换算、超时/限流/重试/取消；不提供生成前用量或金额预测。
- `NetworkPrivacyPolicy`：默认禁用素材上传；用户逐次或按档案授权，显示待上传素材及目的地。

### 6.3 无模型/无网络时的可用性

必须仍可使用：角色建档、导入音频、查看检测结果（仅已有检测能力）、手动转写/情绪标注、脚本导入与编辑、断句、时间轴、Mock Provider 流程验证、项目保存/恢复。

界面需要清晰区分：`未安装`、`已安装未验证`、`已就绪`、`不可用`、`云端未配置`、`配额/权限受限`。

## 7. 性能设计：RTX 3060 Ti 8GB 与 UI 稳定性

### 7.1 必须遵守的原则

- 同一 GPU 上避免 ASR / TTS / 情绪识别等大模型同时常驻造成显存争用；优先沿用 SubCue 现有 GPU 调度，不存在则规划统一资源管理。
- 以**按需加载 + LRU/空闲释放 + 单 GPU 推理并发限制**作为默认候选；不同引擎切换的装载延迟单独统计。
- UI 事件、音频播放、拖动时间轴和滚动波形不应受模型生成阻塞；长音频按分块索引/波形金字塔绘制。
- 仅在参考哈希、模型版本、预处理参数或特征提取版本变化时失效音色缓存；减少重复解码与重复提取。
- 优先重用共享基础模型；不同角色切换只切换参考条件/权重映射，不能默认为每个角色加载完整模型。
- 输入素材处理和推理工作采用有上限的排队、磁盘缓存和内存预算；任务必须可取消，Worker 崩溃不能拖垮 SubCue 主进程。
- 对网络 Provider 规划连接超时、重试退避、速率/费用上限、重复任务防护；**尚未联网时必须可通过 Mock 验证**。

### 7.2 性能观测指标与初始验收建议

| 指标 | Plan 需建立的观测与测试方式 | 初始门槛性质 |
|---|---|---|
| UI 响应性 | 脚本滚动、拖动片段、切角色时测主线程阻塞 | 目标 p95 UI 操作响应 < 100ms（待基线确认） |
| 播放连续性 | 压测同时导入/分析/预览时的 underrun、爆音次数 | 目标 0 次可听见缓冲断裂 |
| GPU 显存峰值 | 逐引擎采集 `peak VRAM` 与切换后的释放情况 | 需在实际模型安装后验证；不预填假数据 |
| 参考缓存命中 | 相同角色连续生成时特征提取次数与耗时 | 目标避免不必要的重复提取 |
| 增量重生成 | 修改 N 段中的 1 段，只新建对应 Take | 正确率 100%（逻辑测试） |
| 项目可靠性 | 强制中断/崩溃/重启后的恢复和资产一致性 | 不丢已提交的档案、脚本与 Take |
| 生成质量 | 中英日朗读正确率、音色、口音、噪声、峰值 | 模型部署后建立实测基准，暂不虚构分数 |
| 磁盘增长 | 同素材多版本缓存、清理与引用计数测试 | 不误删仍被项目引用的文件 |

**性能预算以“待测基线 + 目标 + 实测结果”管理**，不以预测显存/实时率代替真实测试。

## 8. 数据结构、项目迁移与安全

### 8.1 建议数据实体（待对齐既有 DB）

| 实体 | 主要字段 / 关系 | 注意事项 |
|---|---|---|
| `voice_profiles` | UUID、displayName、备注、默认 preset、创建/更新时间 | 角色重命名不改变关联 |
| `voice_assets` | assetId、profileId、原件路径、hash、格式/语种、授权标记 | 原件不可覆盖 |
| `voice_asset_derivatives` | parentAssetId、处理参数、工具版本、路径、hash | 可复现，可重新构建 |
| `voice_annotations` | assetId、转写、情绪预测/人工标签、置信/来源 | 不确定值允许为空 |
| `voice_provider_bindings` | profileId、provider、modelVersion、voiceId/weightPath/refId | 远端 ID 与本地权重区分 |
| `voice_presets` | profileId、默认参考、情绪参考、优先引擎 | 可命名的多音色变体 |
| `voice_segments` | segmentId、原文、朗读文、语言、参数、排序和段落关系 | 变更可追踪 |
| `voice_takes` | segmentId、资产路径、生成输入哈希、Provider 信息、选中状态 | 新生成不覆盖旧 Take |
| `voice_jobs` | 状态、输入快照、失败原因、队列元信息 | 崩溃恢复 / 去重 |

迁移规则：版本化 Schema、先备份、向前兼容旧项目，回滚策略明确；避免将大规模 WAV/模型权重放入 SQLite BLOB。

### 8.2 数据安全与授权

- 默认所有素材、参考转写、权重和生成音频**仅存本地**；没有主动授权不得传给任何云服务。
- 原始素材、派生素材和模型权重分别管理；敏感路径与音色参考不进入普通应用 LOG；API Key 使用操作系统安全凭据服务。
- 只导入/克隆具有适当权限的声音。档案中记录素材授权、来源、用途限制与服务商的声音克隆政策。
- 支持角色完整导出/备份、迁移和删除；明确删除本地资产 ≠ 删除云端音色，云端删除需要单独接口及结果确认。
- 对云端 API 预留数据存储地域、隐私政策、保留期限、训练用途、声音注册验证及请求费用上限字段。
- 对模型目录/权重文件采取来源与校验和校验，不信任不明来源可执行脚本、Pickle 权重及传入的任意路径。
- 将访问控制与本地磁盘加密纳入安全评审；加密只保护相应威胁模型，不宣传可以抵御已解锁账户下的所有恶意程序。

## 10. 必须覆盖的测试矩阵

### 10.1 功能正确性

- [ ] 中文、英文、日语名称；同名角色允许使用内部 UUID 区分，重命名后引用不断裂。
- [ ] 多角色切换、同一角色多种音色预设；不串用其他角色的参考缓存和 Take。
- [ ] 不含情绪标签、不含转写、全静音、严重削波、损坏文件、混合说话人的样本导入。
- [ ] 44.1k/48k/不同模型要求采样率；单双声道与不同编码；音高、播放时长、拼接边界无错误。
- [ ] 片段拆分/合并、改一段、撤销、重试、取消、重新选择旧 Take；其它片段不能失效。
- [ ] 未知 JSON 字段、非法情绪、重复 Segment ID、超长文本、恶意路径/URL 与转义字符。
- [ ] Provider 不支持情绪文本、参考文字或目标语言时，明确错误/降级，不能伪成功。
- [ ] 无模型、无 Key、无网络、显存不足、Worker 退出、磁盘空间不足时的优雅恢复。

### 10.2 音频可靠性与性能

- [ ] 原始 WAV 与缓存处理后的峰值、True Peak、DC Offset、削波报告可比对。
- [ ] 人为构造 Click/Pop、削波、50/60Hz 干扰、截断音频，保证能检测或明确标出检测盲区。
- [ ] 高负载录音/预览/时间轴操作时没有 UI 长时间冻结或实时音频缓冲断裂。
- [ ] 长文本和多版本 Take 的内存、磁盘与查询性能不出现无界增长。
- [ ] 系统崩溃或用户强制结束任务后不会留下已提交但找不到的资产、错乱状态和永久锁。
- [ ] 真正的中英日音色、情绪和口音质量需**待模型部署后**进行盲听/客观评价，不用 Mock 结果冒充音质验收。

### 10.3 安全与合规

- [ ] 默认网络关闭时，未产生声音素材外传。
- [ ] 取消云端许可后不继续后台上传。
- [ ] LOG、异常、导出诊断包中不泄露 Token、原始敏感音频和未许可资料。
- [ ] 删除角色时提示本地引用与远端 Voice ID 的删除范围；不会误删共享基础模型。

## 11. 风险、降级与优先级

| 风险 | 影响 | 默认应对 |
|---|---|---|
| 8GB 显存与模型依赖冲突 | 推理失败、OOM、卡顿 | 独立 Worker、按需加载、GPU 队列、Mock fallback |
| 相同音色跨语种口音不自然 | 中文音调、英文/日文韵律失真 | 切换模型/参考、词典纠音、分语种测试和人工试听 |
| 自动情绪误判 | 样本被错分、合成效果不符 | 预测/人工标签分开、低置信度待审、可关闭自动标注 |
| 参考音频本身削波/底噪 | 克隆不稳定、音色污染 | 非破坏性处理、质量门槛与候选参考 A/B |
| 局部重新生成与邻段不连贯 | 语速/音色/响度跳变 | 相同角色预设、上下文、边界质检、版本对照 |
| Provider 功能不统一 | 指令被静默忽略、用户误解 | `TtsCapabilities` + 显式提示 + 不支持项禁用 |
| 云端 Voice ID 被误认为本地模型 | 离线不可用、资产不可迁移 | 资产类型强区分、Provider 绑定状态明确 |
| 工程侵入过深 | 字幕/粗剪回归、维护成本高 | 先审查、共享服务优先、模块化与分阶段回归 |
| API 费用和隐私规则变化 | 超支、合规风险 | 不锁死价格；费用预算/同意/策略接口预留 |

## 12. Plan 模式需要与用户讨论并形成 ADR 的问题

Codex 在完成仓库审查后，按以下顺序提出**具体、少量、能改变技术方案**的问题，并同时给出推荐默认值与替代方案：

1. **工作区位置**：复用现有项目级时间轴还是先采用 Voice Studio 内的独立轻量时间轴？默认：优先复用现有可扩展时间轴；若侵入大则先轻量独立。
2. **角色声音数据生命周期**：角色档案为全局库还是项目私有？默认：全局角色库 + 项目保存版本快照/引用，以免重命名和档案更新意外影响旧项目。
3. **持久化方式**：复用现有 SQLite Schema/Repo 还是独立命名空间？默认：复用数据库管理及 migration，新增 voice_* 表。
4. **音频工程格式**：既有混音/预览采样率是否允许沿用？默认：保持现有统一格式，只有确认缺乏规范时才讨论 48kHz Float32。
5. **脚本导入格式**：最小 V0 是否支持自由文本与 JSON 两种？默认：两种均支持，结构化 JSON 有版本号及预览。
6. **模型执行边界**：现有推理进程/IPC 是否可复用？默认：复用现有隔离机制；不存在时比较本机 IPC/HTTP 后再决定。
7. **首轮 UI 范围**：纯 Voice Studio 脚本/参考素材/Take 列表，还是深度集成已有粗剪时间轴？默认：先保证数据/任务链路完整，后续整合高级时间轴。
8. **数据使用策略**：是否默认所有档案永不上传云端？默认：是；未来单次授权、可撤销、留存审计。

每个 ADR 需要包含：背景、候选方案、推荐方案、取舍、对现有工程影响、可回退路径与验收条件。
