# SubCue 自动化测试清单

> 覆盖范围：**字幕编辑（自动字幕打轴）**、**自动粗剪**、**AI 配音**三个工作区，以及三者共用的工程存储、设置、媒体与打包能力。
> 明确排除：需要调用**云端付费 API** 的功能（见 §11）。这些功能的协议、脱敏、取消与失败路径仍有假 HTTP 离线覆盖，不产生费用。
> 基线：2026-10-27 本机 `windows-release-cuda` 全量 CTest **35/35 通过（137.65 s）**，其中 12 个用例按需跳过（§2.2）。
> 本文与 `docs/architecture.md` 的测试目标表冲突时，以本文和 `tests/CMakeLists.txt` 为准（architecture.md 该表已过时）。

## 1. 怎么跑

| 目的 | 命令 |
| --- | --- |
| 构建 + 全量测试（推荐） | `tools\build-windows.bat cuda` |
| 只跑测试（已构建） | `ctest --preset windows-release-cuda --output-on-failure` |

| 多目标（两条命令） | `ctest --preset windows-release-cuda -R SubCueEditorIntegrationTests --output-on-failure`；`ctest --preset windows-release-cuda -R SubCueRoughCutControllerTests --output-on-failure` |

| 打包验收 | `tools\package-windows.bat` 后 `ctest --preset windows-release-cuda -R SubCuePackagingTests` |

直接运行测试 exe（不经 CTest）时要补 DLL 搜索路径：

```powershell
$env:PATH = "C:\Qt\6.10.3\msvc2022_64\bin;D:\DSH\SubCue\vcpkg_installed\x64-windows\bin;$env:PATH"
```

### 1.1 两个必须知道的运行事实

1. **CTest 里的 QML 用例是 offscreen 的。** `SubCueAppControllerTests`、`SubCueEditorIntegrationTests`、`SubCueRoughCutControllerTests`、`SubCuePackagingTests` 在 `tests/CMakeLists.txt` 里都设置了 `ENVIRONMENT "QT_QPA_PLATFORM=offscreen"`（TIMEOUT 120/30/60）。
   → offscreen 只能证明**状态、几何、可见性、业务语义**；**中文字体、DPI 排版、原生控件观感必须用 Windows 平台插件另跑**（`docs/UnifiedExperienceValidation.md` 也这样约定）。
2. **`qmlImportDropAndLayout` 加载的是旧界面 `Main.qml`**，不是运行期的 `AppRouter.qml`/`SubtitleWorkspace.qml`。`qmlShortcutsMatchFeatureMatrix` 把 `Main.qml` 当冻结基线，只比对 `SubtitleWorkspace.qml` 的快捷键集合。
   → 不要把 `Main.qml` 的覆盖当成当前字幕工作区的 UI 覆盖；`RoughCutWorkspace.qml`、`VoiceWorkspace.qml` 的快捷键**没有**被任何矩阵测试冻结。
3. **跑全量 CTest 前必须关掉正在运行的 SubCue 实例。** 云端凭据相关用例（`cloudSettingsDraftAndDiscovery`、`cloudDeletionWaitsForOwner`、`unifiedAiKeySaveClearAndRollback`、`cloudSwitchConflictAndCapability`、`voiceCloudUpdateRevisionAndCancellation`、`voiceFlashUsageAndUnknownResultsAreProtected`、`omniReviewStartsAtZeroProgress`）会与运行中的实例争用同一 Windows 凭据域，2026-10-28 实测：SubCue 开着跑 CTest → 7 个用例 `cloud.save()` 失败；关掉实例后全绿。

### 1.2 夹具与环境

- 媒体夹具：`tests/media/`（`audio.wav`、`cfr_av.mp4`、`vfr.mp4`、`corrupt.bin`、`script_sample.docx`），由 `SUBCUE_TEST_MEDIA_DIR` 注入。
- 基线夹具：`tests/golden/`（对齐 golden、SRT/ASS 基线、时间码用例、脱敏 ASR 响应），由 `SUBCUE_TEST_GOLDEN_DIR` 注入。
- 模型权重在仓库外（`SUBCUE_MODELS_ROOT`，默认 `E:/AIModels/ASR/models`）；普通回归不加载模型。
- 配音的 Mock 生成/质检/任务用例需要独立解释器 `E:/AIModels/TTS/.venv/Scripts/python.exe`（本机存在，因此这些用例实际执行；换机器缺失时整组 SKIP）。另有两条依赖 `sourcePath(".venv-inference/Scripts/python.exe")`。
- QML 截图落在忽略目录 `.test_tmp/`（`grabWindow()` 产物），可人工复核布局。

## 2. 判定标准

1. 只看 CTest 退出码与 `100% tests passed, 0 tests failed out of 35`；`QSKIP` 不计失败，但新增 SKIP 必须写明原因。
2. **复现优先**：修缺陷时必须先让用例红（把缺陷放回去），再让它绿；从未失败过的检查等于没加。
3. UI 用例判定 = 真实 QML 加载无 `QQmlEngine::warnings` + 控件可见性/文本/几何断言 +（offscreen）截图复核布局。
4. Mock、夹具音频只证明流程、数据、取消与生命周期，**不证明真实模型音质或真实识别率**（§13）。
5. 不得为了变绿放宽断言、删除用例或跳过失败目标。

## 13. 维护约定

1. 新增用户可见功能时，先在本清单加一行（编号 + 触发路径），再补测试；缺口行写清原因，不要把「没测」写成「已覆盖」。
2. 改媒体/播放/存储核心：至少跑 `SubCueMediaTests`、`SubCuePlaybackTests`、`SubCueCacheWaveformTests`、`SubCueProjectStoreTests`、`SubCueEditorIntegrationTests`。
3. 改 QML 交互：至少跑 `SubCueEditorIntegrationTests` + `SubCueSourceHygieneTests`（快捷键冻结与资源注册）。
4. 改打包或依赖：必须过 `SubCuePackagingTests` + 两个启动冒烟。
5. 修缺陷：先写会红的用例（缺陷放回去必须失败），再修到绿；做不到的检查不算检查。
6. 用例改名/删除时同步本表；本文与 `tests/CMakeLists.txt`、`tests/cpp/` 同源，冲突以代码为准。
7. 真实模型、真实设备、付费服务的验收结论只能来自显式启用的用例与人工复核，不得用 Mock 结果代替（详见 `docs/UnifiedExperienceValidation.md` 的验证边界）。
