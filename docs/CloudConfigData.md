# 云端账号、模型与任务绑定数据层

`ApplicationContext` 持有 `CloudConfigStore`，数据库为设置目录内现有 `connections.sqlite`。本阶段只接入数据层，业务请求仍走原控制器；设置管理页与快速切换将在下一阶段接入，不会因数据库迁移发起任何云端请求。

## 数据与兼容

Schema 1 使用 `cloud_meta` 保存版本、稳定存储身份和配置代次；`cloud_accounts`、`cloud_models`、`cloud_bindings` 各按稳定主键保存经过白名单校验的 JSON 元数据。`cloud_verifications` 为后续验证结果提供独立表。密钥只进入凭据库，不进入这些 JSON 或数据库文件。

账号允许百炼北京/新加坡、DeepSeek、Moonshot。模型指定实际 ID、所属账号、协议适配器、显示名、Workspace 和启用状态。非百炼账号不能绑定尚未实现的音频协议。五个固定任务均保留记录，未配置的目标为空；识别目标允许现有本地引擎。

首次初始化只迁移旧识别、听音复核和 TTS 连接的非敏感资料，保持无法确认相同的账号分开。旧凭据引用不导入。原 `cloud_connections` 表保留，当前设置页仍可使用；本阶段之后在旧设置入口编辑的连接不会自动覆盖新模型目录，后续 UI 接入需显式协调。

## 保存与凭据生命周期

- `load` 返回不含密钥的账号、模型、绑定及配置版本。
- `save` 接收完整草稿、预期版本、按账号指定的 Keep/Replace/Remove 动作。厂商和地域属于不可变账号身份，变更时必须新建账号。
- 新密钥写入 `SubCue/Cloud/<存储身份>/<随机版本>`，SQL 提交后才退休旧版本。写入失败或 SQL 写入失败保留原配置；提交结果未确认时保留新旧凭据，之后依据实际引用清理。
- 保存成功但删除旧凭据失败仍返回保存成功，并通过错误文本报告清理待重试。不得因此回滚已提交的新引用。
- `resolveTask` 在同一个跨进程锁内读取任务、模型、账号并加载凭据，返回元数据快照，通过独立输出参数交付任务密钥。后续切换或轮换不改变已经启动的任务副本。
- `cleanup` 仅枚举当前存储身份下未引用的版本。数据库损坏、Schema 不兼容或验证表不可读时停止清理。其他配置库、旧版凭据及其他应用不在清理范围。

这些操作复用相邻 `.cloud.lock` 的短时跨进程锁。调用方执行 Remove、删除账号或清除全部前，必须先停止新任务、取消并等待使用该账号的现有任务；数据层不越权控制业务任务。

## 验证

`SubCueCloudConfigTests` 使用内存假凭据覆盖迁移、重新读取、轮换、冻结任务、配置冲突、SQL 故障、写入/删除凭据失败、清理作用域及损坏库保护；另以隔离测试命名空间验证 Windows 凭据枚举，测试结束删除该条测试凭据。真实密钥和付费服务不参与测试。
